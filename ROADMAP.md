## 1.1 🔴 Авторизация через Telegram

**Статус:** 🔄 В процессе (фронтенд + edge function готовы, нужно создать бота и запустить миграцию)  
**Важность:** Критично — без этого нет SaaS

### Почему Telegram, а не email/пароль:
- 95%+ продавцов на маркетплейсах активно пользуются Telegram
- Нет проблемы «забыл пароль»
- Быстрый вход — не надо заполнять форму
- Telegram Login Widget — официальный OAuth от Telegram, бесплатный

### Как реализовать:

**Шаг 1: Telegram Bot**
```
1. Создать бота через @BotFather → получить BOT_TOKEN
2. В настройках бота включить: /setdomain → указать домен продукта
3. Хранить BOT_TOKEN в .env (никогда в коде)
```

**Шаг 2: Frontend — виджет входа**
```html
<!-- Размещается на /login странице -->
<script async src="https://telegram.org/js/telegram-widget.js?22"
  data-telegram-login="ВАШ_БОТ_USERNAME"
  data-size="large"
  data-onauth="onTelegramAuth(user)"
  data-request-access="write">
</script>
<script>
  function onTelegramAuth(user) {
    // user = { id, first_name, last_name, username, photo_url, auth_date, hash }
    // Отправить на backend для верификации
    fetch('/api/auth/telegram', {
      method: 'POST',
      body: JSON.stringify(user)
    })
  }
</script>
```

**Шаг 3: Backend — верификация подписи**
```typescript
// Telegram присылает hash — его нужно верифицировать через HMAC-SHA256
// чтобы убедиться что данные не подделаны
import crypto from 'crypto';

function verifyTelegramAuth(data: Record<string, string>, botToken: string): boolean {
  const { hash, ...fields } = data;
  const checkString = Object.keys(fields)
    .sort()
    .map(k => `${k}=${fields[k]}`)
    .join('\n');
  const secretKey = crypto.createHash('sha256').update(botToken).digest();
  const hmac = crypto.createHmac('sha256', secretKey).update(checkString).digest('hex');
  return hmac === hash && (Date.now() / 1000 - parseInt(fields.auth_date)) < 86400;
}
```

**Шаг 4: Сессия / JWT**
```
После верификации:
1. Создать/найти пользователя в Supabase (таблица users) по telegram_id
2. Выдать JWT токен (accessToken + refreshToken)
3. Хранить в localStorage / httpOnly cookie
4. Все API-запросы с заголовком: Authorization: Bearer <token>
```

## 1.2 🔴 Система Компаний (мультиаккаунт)

**Статус:** 🔄 В процессе (UI + сервисы готовы, нужно запустить SQL-миграцию в Supabase)  
**Важность:** Критично

### Концепция:
```
Один пользователь → много компаний
Одна компания → много пользователей (совместная работа)

Пример: Менеджер маркетплейсов работает в 3 компаниях.
Он входит по Telegram → видит список своих компаний → 
выбирает нужную → попадает в рабочее пространство этой компании.
Все данные (группы товаров, магазины, аналитика) изолированы по компании.
```

### Флоу после первого входа:
```
1. Новый пользователь → нет компаний → экран "Создайте компанию"
2. Заполняет форму (см. ниже)
3. Компания создана → попадает в рабочий стол
4. Следующие входы → если 1 компания → сразу в неё
                   → если несколько → экран выбора компании
```

### Форма создания компании:
```
Обязательные поля:
  - Название компании (любое, например "Мой магазин WB" или "ООО Ромашка")

Необязательные поля (для реквизитов — нужны для выгрузки документов):
  - Тип: ИП / ООО / Самозанятый / Физ.лицо
  - ИНН
  - КПП (только для ООО)
  - ОГРН / ОГРНИП
  - Юридический адрес
  - Расчётный счёт
  - БИК банка
  - Название банка
  - Кор. счёт
  - Email для документов
  - Телефон
  
Дополнительно:
  - Логотип компании (upload изображения)
  - Цвет метки (для различения компаний в переключателе)
```

### Переключение между компаниями:
```
UI: В левом верхнем углу (сейчас там логотип ChairCharm) → 
    кликабельный блок с названием текущей компании + стрелка вниз → 
    дропдаун со списком всех компаний пользователя + кнопка "Добавить компанию"
```

### Таблицы Supabase:
```sql
-- Компании
CREATE TABLE companies (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL,
  type TEXT CHECK (type IN ('ip', 'ooo', 'self_employed', 'individual')),
  inn TEXT,
  kpp TEXT,
  ogrn TEXT,
  legal_address TEXT,
  bank_account TEXT,
  bik TEXT,
  bank_name TEXT,
  corr_account TEXT,
  email TEXT,
  phone TEXT,
  logo_url TEXT,
  color TEXT DEFAULT '#005bff',
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Связь пользователь ↔ компания (роли)
CREATE TABLE company_members (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  company_id UUID REFERENCES companies(id) ON DELETE CASCADE,
  user_id UUID REFERENCES users(id) ON DELETE CASCADE,
  role TEXT CHECK (role IN ('owner', 'admin', 'manager', 'viewer')) DEFAULT 'owner',
  invited_by UUID REFERENCES users(id),
  joined_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(company_id, user_id)
);

-- Все существующие таблицы (boxes, products и т.д.) получают поле:
ALTER TABLE boxes ADD COLUMN company_id UUID REFERENCES companies(id);
-- + Row Level Security (RLS) чтобы пользователь видел только свои данные
```

### Row Level Security (RLS) в Supabase:
```sql
-- Пользователь видит только данные компаний, в которых он состоит
CREATE POLICY "boxes_company_isolation" ON boxes
  USING (company_id IN (
    SELECT company_id FROM company_members WHERE user_id = auth.uid()
  ));
```

### Роли внутри компании:
```
owner   — полный доступ, может удалить компанию, управлять участниками
admin   — полный доступ к данным, может добавлять/удалять менеджеров
manager — может редактировать товары, заказы, настройки магазинов
viewer  — только просмотр, без редактирования
```

## 2.2 🟡 Репрайсер (Автоматическое изменение цены)

**Статус:** ✅ Базовая версия реализована (RepricerModule — 1 585 строк + подмодули)  
**Важность:** Высокая — экономит часы ручной работы

### Правила репрайсера (задаются пользователем):
```
Правило 1: "Быть на X₽ ниже конкурента"
  - Следить за артикулом конкурента
  - Если конкурент снизил цену → я снижаю на X₽
  - Минимальная цена = не ниже себестоимости × 1.2 (настраивается)

Правило 2: "Держать позицию в топ-3 по цене в категории"
  - Мониторинг топ-3 продавцов в категории
  - Автокоррекция цены

Правило 3: "По расписанию"
  - В будни 09:00 цена X₽
  - В выходные цена Y₽
  - Ночью +5% (меньше конкуренции)

Правило 4: "По остатку"
  - Если остаток < 10 шт → поднять цену на 15% (дефицитный товар)
  - Если остаток > 100 шт → снизить на 5% (ускорить продажи)
```

### Архитектура:
```
1. Фоновый воркер (cron каждые 30-60 минут):
   - Считывает активные правила из БД
   - Для каждого правила получает текущие цены конкурентов
   - Вычисляет новую цену
   - Если цена изменилась → обновляет через API маркетплейса
   - Пишет лог изменения в финансовый журнал

2. UI (новый модуль):
   - Список правил для каждого товара/группы
   - История изменений цен (когда, почему, на сколько)
   - Статус: активно / пауза / ошибка
```

## Философия

```
Аналитические сервисы (Moneyplace, MPStats):
  → "Вот ваши данные. Вот что происходит на рынке."
```
