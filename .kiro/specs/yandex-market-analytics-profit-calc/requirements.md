# Requirements Document

## Introduction

Модуль аналитики показывает неверную чистую прибыль для Yandex.Market - 1.2M вместо фактической выплаты 460K. Система использует неверную метрику выручки (цену для клиента вместо фактической выплаты продавцу) и не учитывает все расходы, связанные с продажами на Yandex.Market. Даже без учета себестоимости (COGS) прибыль должна быть около 460K, что соответствует фактическим выплатам Yandex.Market.

## Glossary

- **Analytics_Module**: Модуль аналитики, отвечающий за расчет прибыли и других финансовых показателей
- **Yandex_Market**: Маркетплейс Яндекс.Маркет, на котором пользователь продает товары
- **Gross_Revenue**: Валовая выручка - фактическая сумма, полученная от Yandex.Market после всех вычетов
- **COGS**: Себестоимость проданных товаров (Cost of Goods Sold), устанавливается в репрайсере отдельно
- **Marketplace_Fees**: Комиссии и сборы маркетплейса (комиссия, логистика, маркетинг, услуги)
- **Net_Profit**: Чистая прибыль = Валовая выручка - COGS - Marketplace_Fees - Tax
- **Transaction**: Финансовая транзакция из mp_transactions, содержащая данные о продажах
- **Yandex_Market_API**: API Яндекс.Маркета для получения точных данных о выручке и расходах

## Requirements

### Requirement 1: Точный расчет валовой выручки Yandex.Market

**User Story:** Как владелец бизнеса, я хочу видеть фактическую валовую выручку от Yandex.Market, чтобы понимать реальные поступления от продаж.

#### Acceptance Criteria

1. WHEN Analytics_Module рассчитывает валовую выручку для Yandex.Market THEN система SHALL использовать фактическую выплату продавцу вместо цены для клиента
2. WHERE доступны поля `amount` или `accruals_for_sale` в транзакциях THEN Analytics_Module SHALL использовать эти поля как базовую выручку
3. IF транзакция Yandex.Market не содержит точных данных о выплате THEN система SHALL использовать расчетную выручку на основе известных ставок комиссий
4. FOR ALL Yandex.Market транзакций за период расчетная выручка SHALL соответствовать фактическим выплатам Yandex.Market с точностью ±5%

### Requirement 2: Полный учет расходов маркетплейса

**User Story:** Как финансовый аналитик, я хочу видеть все расходы, связанные с продажами на Yandex.Market, чтобы точно рассчитывать чистую прибыль.

#### Acceptance Criteria

1. WHEN Analytics_Module рассчитывает чистую прибыль THEN система SHALL учитывать все категории расходов: комиссии, логистика, маркетинг, услуги маркетплейса
2. WHERE данные о расходах доступны через Yandex_Market_API THEN система SHALL интегрироваться с API для получения точных значений
3. WHERE API недоступен THEN система SHALL использовать исторические данные и стандартные ставки из mp_transactions
4. FOR EACH расходной категории расчетный расход SHALL соответствовать фактическим списаниям Yandex.Market с точностью ±10%

### Requirement 3: Корректная формула расчета чистой прибыли

**User Story:** Как владелец бизнеса, я хочу видеть точную чистую прибыль от продаж на Yandex.Market, соответствующую фактическим выплатам.

#### Acceptance Criteria

1. THE Analytics_Module SHALL рассчитывать чистую прибыль по формуле: Net_Profit = Gross_Revenue - COGS - Marketplace_Fees - Tax
2. WHEN COGS не установлен в системе THEN Analytics_Module SHALL рассчитывать прибыль без учета себестоимости с явным указанием этого
3. IF имеются расхождения между расчетной и фактической прибылью > 10% THEN система SHALL предоставлять детальный анализ расхождений
4. FOR ALL периодов расчета разница между расчетной чистой прибылью и фактическими выплатами Yandex.Market SHALL быть ≤ 5%

### Requirement 4: Интеграция с Yandex.Market API (опционально)

**User Story:** Как разработчик, я хочу интегрировать модуль аналитики с Yandex.Market API, чтобы получать максимально точные финансовые данные.

#### Acceptance Criteria

1. WHERE пользователь настроил доступ к Yandex_Market_API THEN Analytics_Module SHALL использовать API для получения точных данных о выручке и расходах
2. WHEN Analytics_Module обращается к API THEN система SHALL кэшировать данные для минимизации запросов
3. IF API недоступен или возвращает ошибку THEN система SHALL автоматически переключаться на локальные данные с уведомлением пользователя
4. FOR EACH категории данных (выручка, комиссии, логистика, маркетинг) интеграция с API SHALL обеспечивать точность данных ≥ 95%

### Requirement 5: Обратная совместимость и регрессионное тестирование

**User Story:** Как владелец продукта, я хочу, чтобы исправление расчета прибыли не сломало существующую аналитику для других маркетплейсов.

#### Acceptance Criteria

1. WHEN Analytics_Module рассчитывает прибыль для других маркетплейсов (WB, Ozon) THEN система SHALL CONTINUE TO использовать существующие корректные методы без изменений
2. FOR ALL существующих функций аналитики исправление расчета прибыли Yandex.Market SHALL NOT влиять на их работу
3. IF изменение вносит регрессии в другие части системы THEN система SHALL автоматически запускать регрессионные тесты
4. WHERE изменяется формат данных или расчеты THEN система SHALL предоставлять инструменты миграции для существующих данных

### Requirement 6: Валидация и отчетность

**User Story:** Как пользователь, я хочу получать понятные отчеты о расчетах прибыли с возможностью проверки каждого этапа.

#### Acceptance Criteria

1. WHEN Analytics_Module рассчитывает прибыль THEN система SHALL предоставлять детализированный отчет с разбивкой по компонентам: Gross_Revenue, COGS, Marketplace_Fees, Tax, Net_Profit
2. FOR EACH расчета система SHALL сохранять исторические данные для последующего аудита
3. IF возникают подозрительные значения или расхождения THEN система SHALL генерировать предупреждения для пользователя
4. WHERE пользователь проверяет расчет THEN система SHALL предоставлять возможность ручной корректировки и повторного расчета
