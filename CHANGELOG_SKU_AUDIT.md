## Как это работает

### Фильтры
1. **По оценке** (A/B/C/D) — клик на KPI-карточку
2. **По маркетплейсу** (WB/Ozon/ЯМ) — клик на KPI-карточку МП
3. **По магазину** — дропдаун в тулбаре (показываются только магазины выбранного МП)
4. **Поиск** — по названию товара, артикулу, бренду, названию магазина

### Редактирование карточек
- Открываешь карточку → видишь проблемы → кликаешь «Исправить»
- Меняешь название/бренд/фото → жмёшь «Сохранить»
- **Автоматически** отправляется в МП и через 2 сек загружаются свежие данные
- Модальное окно закрывается автоматически
- В списке появляется бейдж «На модерации» → после применения изменится на «Обновлено»

### Структура данных
```typescript
interface AuditItem {
  id: string;
  marketplace: 'wb' | 'ozon' | 'yandex';
  storeId: string;
  storeName: string;  // ← НОВОЕ

  vendorCode: string;
  brand: string;
  category: string;
  photoCount: number;
  score: number;
  grade: 'A' | 'B' | 'C' | 'D';
  issues: string[];
  tips: string[];
  // ...
}
```

## Технические детали

### Файлы изменены:
- `/src/modules/SkuAuditModule.ts` — основной модуль

### Зависимости:
- `wbDb`, `ozonDb`, `yandexDb` — загрузка товаров и магазинов
- `ozonApi`, `yandexApi` — отправка изменений
- `skuEditLog` — журнал изменений (localStorage)

### API-методы:
- **Ozon**: `POST /v2/product/import` (обновление товара)
- **ЯМ**: `POST /businesses/{businessId}/offer-mappings/update` (обновление названия)
- **WB**: не поддерживается через API (только ручное редактирование в ЛК)
