# История развития — autoYan

Автоматизация заполнения данных доставки в Яндекс Маркете.


---

## Архитектура системы

### Скрипты
- **kur.py** — автозаполнение страницы "Ваши курьеры" (работает)
- **tariff.py** — автозаполнение страницы "Тарифы на доставку" (в разработке)

### Режимы работы (kur.py)

| Режим | Описание |
|-------|----------|
| С картой | Использует готовую карту путей (karta.json), быстрое заполнение |
| Без карты | Пошаговое раскрытие регионов, заполнение значения "20", построение карты |
| Анализ | Сбор данных по всем позициям, Excel-отчёт с результатами |
| Сканер | Построение полной карты путей, сохранение в karta.json |

### Режимы работы (tariff.py)
- Заполнение городов по зонам (чекбоксы) — на основе Excel из папки `Склады города/`


---

## Параллельный режим

### Общее описание
Одновременная обработка нескольких складов, каждый склад в отдельном терминале.

### Порядок работы
1. Выбрать "Параллельный режим"
2. Выбрать подрежим (С картой / Без карты / Анализ / Сканер)
3. Выбрать склады через пробел (например: "4 8" для МХ-Пенза и ХМ-Пенза)
4. Система создаёт временные конфигурации и запускает терминалы
5. Пользователь авторизуется в каждом браузере и нажимает Enter
6. Скрипты работают независимо
7. Главный терминал показывает статус всех процессов

### Структура конфигурации (передаётся через временный JSON)
```json
{
  "YD_START_URL": "https://partner.market.yandex.ru/shop/.../delivery?warehouseId=...",
  "YD_CABINET": "МХ",
  "YD_WAREHOUSE": "Пенза",
  "YD_MODE": "Анализ",
  "YD_CITIES": ["Город1", "Город2"],
  "YD_PROFILE_DIR": "profiles/browser_profile_МХ_Пенза",
  "YD_INSTANCE_NAME": "МХ-Пенза"
}
```

### Ограничения
- Максимум 12 параллельных процессов (по количеству складов)
- Задержка 3 секунды между запусками терминалов
- Каждый кабинет-склад имеет отдельный профиль браузера


---

## Профили браузера

```
profiles/
├── browser_profile_МХ_Пенза/
├── browser_profile_ХМ_Пенза/
├── browser_profile_ТС_Пенза/
├── tariffs_МХ_Пенза/
└── browser_profile/              # Базовый профиль
```

- Каждый кабинет-склад имеет отдельный профиль
- Профили содержат куки и сессии Яндекс Маркета
- kur.py использует `browser_profile_*`, tariff.py — `tariffs_*` или `browser_profile_*`

## Формат Excel-шаблонов

### Тарифы по зонам (Склады зоны/)

| Зона 1 | Зона 2 | Зона 3 | Зона 4 | Зона 5 |
|--------|--------|--------|--------|--------|
| 299    | 399    | 499    | 599    | 699    |
| 3000   | 4000   | 5000   | 6000   | 7000   |
| 0      | 0      | 0      | 0      | 0      |
| 1000   | 1000   | 1000   | 1000   | 1000   |

- Строка 1: заголовки ("Зона 1", "Зона 2" и т.д.)
- Строка 2: цена доставки (руб)
- Строка 3: бесплатная доставка от (руб)
- Строка 4: вес от (г)
- Строка 5: вес до (г)

### Города по зонам (Склады города/)

| Зона 1    | Зона 2      | Зона 3         | Зона 4   | Зона 5    |
|-----------|-------------|----------------|----------|-----------|
| Москва    | Мытищи      | Ногинск        | Тула     | Ярославль |
| Химки     | Люберцы     | Электросталь   | Калуга   | Иваново   |
| Балашиха  | Красногорск | Орехово-Зуево  | Рязань   | Кострома  |

- Строка 1: заголовки с "зона" + номер
- Строки 2+: названия городов

### Простые списки городов (Склады/)

- Один столбец "Город" или "Населённый пункт"
- Используется в kur.py

### Требования к файлам
- Формат: .xlsx
- Заголовки обязательны, должны содержать "зона" и номер
- Имена файлов: `Город.xlsx` (например `Пенза.xlsx`)

## Структура страниц Яндекс Маркета

### "Ваши курьеры" (kur.py)
- Селекторы строк: `tr[data-tid]`
- Кнопка открытия: `button[data-e2e='couriers-delivery-regions-drawer']`
- Indent-классы НЕ используются
- Кнопка сохранения в stickyBar

### "Тарифы на доставку" (tariff.py)
- Селекторы строк: `tr[data-e2e='levitan-table-row']`
- Indent-классы: `__use--indent_N___` (0-4)
- Кнопка настройки: `[data-e2e='levitan-button tariff-setting-setup-button']`
- Drawer wrapper: `[data-e2e='levitan-drawer-wrapper']`
- Таблица дерева: `[data-levitan-table]`
- Чекбоксы: `span[data-e2e^='levitan-clickable checkbox-']`
- Кнопка сохранения: `[data-e2e='levitan-button tariff-setting-save-button']`
- Секция "Где применяется": `[data-e2e-i18n-key*='tariff-table.title']`

### Структура дерева регионов (tariff.py)
```
indent 0: Все регионы • 8
  indent 1: Центральный федеральный округ • 18
    indent 2: Москва и Московская область • 62
      indent 3: Москва (лист)
      indent 3: Городской округ Долгопрудный • 1
        indent 4: Долгопрудный (лист)
```

HTML-дампы структуры хранятся в `Структура Я/`.

## История исправлений

### Апрель 2026 — Исправления kur.py

**Drawer закрывался во время работы (КРИТИЧНО)**
- Причина: `scroll_into_view_if_needed()` скроллил всю страницу, триггерил закрытие
- Решение: функция `scroll_drawer_gently()` — скроллит ТОЛЬКО контейнер drawer

**Drawer закрывался при сохранении**
- Решение: `save_page_changes()` ждёт до 30 секунд закрытия drawer, проверяет видимость кнопки "Настроить"

**Кнопка "Настроить" не находилась после reload**
- Решение: увеличены попытки (5), ожидание `networkidle`, увеличены таймауты

**Лишние перезагрузки**
- Решение: reload только если это не последний округ в списке

### Май 2026 — Полная переработка tariff.py

**Неправильные DOM-селекторы**
- Было: `tr[data-tid]` (селекторы от страницы курьеров)
- Стало: `tr[data-e2e='levitan-table-row']` (правильные для страницы тарифов)

**Excel из неправильной папки**
- Было: `Склады/` (нет зонных колонок)
- Стало: `Склады города/` (с зонами)

**Дерево не раскрывалось**
- Было: только 1 уровень загружался
- Стало: `expand_district_fully()` с пакетной обработкой по 3 узла (как в kur.py)

**Парсинг имён тарифов ломался**
- Было: `\n` и "Включен/Выключен" в названиях
- Стало: очистка через `re.sub`

**Drawer не защищён от закрытия**
- Добавлены: `lock_drawer_open()`, `dismiss_overlays()`

**Конфликт логов и профилей**
- Логи: `tariffs_main.log` (было `delivery_main.log`)
- Профили: `tariffs_*` (было общий профиль с kur.py)

**Fallback браузер терял авторизацию**
- Убран `pw.chromium.launch()`, только `launch_persistent_context`

**Нечестное логирование**
- Добавлена верификация после каждого действия (чекбокс отмечен? сохранение прошло?)

### Май 2026 (позже) — Исправление drawer тарифов

**Drawer открывался но дерево не загружалось**
- Причина: React рендерит `<tr>` раньше чем `<button aria-expanded>` внутри них
- Решение: `wait_for_tree_interactive()` — ждёт появления кнопок раскрытия

**Нет скролла к секции дерева**
- Решение: `scroll_to_tree_section()` — 4 способа скролла внутри drawer

**Определение drawer по неправильному признаку**
- Было: наличие любого `tr[data-e2e='levitan-table-row']`
- Стало: проверка `[data-e2e='levitan-drawer-wrapper']` + `button[aria-expanded]`

**Диагностика состояния drawer**
- Добавлена `_diagnose_drawer_state()` — полная JS-диагностика что видно в DOM
