# Техническое задание — STOCKBASE (Product Manager)

## 1. Описание проекта

**Название:** STOCKBASE — Product Manager
**Тип:** Веб-приложение для управления товарными базами, заточенное под Ozon-шаблоны.
**Назначение:** Импорт, хранение, редактирование, фильтрация и экспорт товарных позиций, сгруппированных в логические «коробки». Ориентировано на работу с категориями мебели и сопутствующих товаров.

## 2. Архитектура

**Фронтенд:** Single-Page Application в одном файле `index.html` (HTML + CSS + Vanilla JS).
**Бэкенд:** Supabase (PostgreSQL + REST API).
**Внешние библиотеки (CDN):**
- `xlsx.js` (SheetJS) — парсинг и генерация Excel-файлов.
- Google Fonts: Syne (заголовки), DM Sans (текст).

**Текущее состояние:** Прототип с захардкоженным Supabase anon-ключом. Без сборки, без npm, без модулей.

## 4. Модель данных (Supabase)

### Таблица `boxes`
| Поле | Тип | Описание |
|---|---|---|
| `id` | uuid (PK) | Уникальный ID коробки |
| `name` | text | Название (например «Шкафы май 2025») |
| `sticker` | text | Эмодзи-стикер (любой Unicode-эмодзи) |
| `created_at` | timestamp | Дата создания |

### Таблица `sheets`
| Поле | Тип | Описание |
|---|---|---|
| `id` | uuid (PK) | ID импорта |
| `box_id` | uuid (FK → boxes.id) | К какой коробке относится |
| `filename` | text | Имя загруженного xlsx-файла |
| `columns` | jsonb / text[] | Столбцы импорта |
| `imported_at` | timestamp | Когда импортировано |

### Таблица `products`
| Поле | Тип | Описание |
|---|---|---|
| `id` | uuid (PK) | ID товара |
| `box_id` | uuid (FK → boxes.id) | Коробка-владелец |
| `sheet_id` | uuid (FK → sheets.id) | Импорт-источник |
| `data` | jsonb | Все поля товара как JSON (динамические столбцы) |
| `created_at` | timestamp | Когда добавлен |
| `updated_at` | timestamp | Когда последний раз обновлён |

**Каскадное удаление:** настроить `ON DELETE CASCADE` для `products.box_id → boxes.id` и `products.sheet_id → sheets.id`.

## 5. Безопасность

**КРИТИЧНО:** В текущей версии Supabase anon-ключ зашит в коде (строка ~712 `index.html`). Любой посетитель сайта может через DevTools читать/писать всю базу.

**Что нужно сделать:**
1. Включить **Row Level Security (RLS)** на всех трёх таблицах.
2. Настроить политики (policy):
   - Анонимный доступ можно оставить (если не нужна авторизация), но ограничить операции.
   - При появлении пользователей — добавить таблицу `users`, поле `user_id` в `boxes`, политики «user can only see their own boxes».
3. Реализовать аутентификацию (Supabase Auth — email/password или magic link).
4. Опционально: вынести ключ в build-time переменную или прокси-серверлесс-функцию.

## 6. Функциональные требования

### 6.1 Управление коробками (`boxes`)
- ✅ **Создать коробку** — модалка с инпутом названия.
- ✅ **Переименовать коробку** — компактная модалка:
  - Большой эмодзи-инпут (74×84 px) — тап вызывает системную клавиатуру устройства, можно ввести **любой** эмодзи.
  - Поле названия рядом.
  - Подсказка с инструкцией (адаптируется под iOS / Android по `userAgent`).
  - Горизонтальная лента быстрого выбора (20 курированных эмодзи).
- ✅ **Управление коробкой** (`editBox`) — модалка показывает все колонки/ряды и список товаров с возможностью удалить колонку или отдельный товар.
- ✅ **Удалить коробку** — с подтверждением. Каскадно удаляет товары и листы.
- ✅ **Стикер** — любой эмодзи, рендерится в сайдбаре и мобильной шторке.
- ✅ **Счётчик товаров** — асинхронно подгружается через `Prefer: count=exact`.

### 6.2 Импорт товаров
- ✅ Drag-and-drop xlsx файла или клик по зоне.
- ✅ Поддержка двух форматов:
  - **Ozon шаблон** — заголовки из строки 2, данные с 5-й (1, 3, 4 игнорируются).
  - **Системный формат** — заголовки из строки 1, данные со строки 2.
- ✅ Превью файла — список столбцов (чекбоксы) + список позиций (чекбоксы).
- ✅ Кнопки «Все / Снять» для столбцов и для позиций.
- ✅ Проверка дубликатов по `Артикул*`:
  - Если артикул совпадает и данные те же → пропуск.
  - Если артикул совпадает и данные отличаются → модалка с конфликтами, выбор: обновить / пропустить.
- ✅ Обнаружение новых столбцов (которых не было в коробке) → модалка с выбором: импортировать все / только существующие.
- ✅ Batch-вставка по 100 записей.
- ✅ Отчёт по итогу (добавлено / обновлено / пропущено).

### 6.3 Экспорт товаров
- ✅ Модалка с выбором столбцов и позиций (чекбоксы).
- ✅ «Все / Снять» для каждой группы.
- ✅ Скачивание xlsx через `XLSX.writeFile`.
- ✅ Имя файла: `<box-name>_<YYYY-MM-DD>.xlsx`.
- ✅ Экспорт одного товара — кнопка в карточке детали.

### 6.4 Просмотр товаров
- ✅ Два режима: **Таблица** и **Карточки**, переключаются вкладкой.
- ✅ Skeleton-загрузка при переключении (для больших списков).
- ✅ В таблице:
  - Колонка с миниатюрами (38×38 px) если есть «Ссылка на главное фото*».
  - Сортировка по любому столбцу (asc/desc, тип определяется автоматически).
  - Подсветка совпадений с поисковой строкой через `<mark>`.
- ✅ В карточках:
  - Сетка `auto-fill, minmax(200px, 1fr)` (десктоп) / 2 колонки (мобила).

- Топбар: поиск (макс 460px) + кнопки Импорт / Экспорт / Коробка.

- **Sidebar и filter-panel полностью скрыты** (`display:none`).
- **Нижняя нав-панель** (5 кнопок):
  - Коробки (открывает bottom-sheet)
  - Все
  - **FAB** жёлтый (54×54) — Импорт
  - Фильтры (открывает bottom-sheet)
  - Экспорт
- **Bottom sheets** для коробок и фильтров — ручка-полоска сверху, выезжают снизу с blur-backdrop.
- **Поиск sticky сверху**, контрастный фон, крупный шрифт (15px).
- **Карточки 2 колонки**, фото 140px, скруглены 12px.
- **Модальные окна** превращаются в bottom-sheets — на всю ширину, с ручкой-полоской.

## 8. Известные проблемы и техдолг

### Критичные
1. **RLS не включён** — публичный доступ к БД (см. раздел 5).
2. **Нет аутентификации** — нет понятия «пользователь».
3. **Нет виртуализации** — при 10k+ товаров рендер тормозит.
4. **Нет offline / кэша** — без интернета приложение не работает.

### Средние
5. **Race conditions** при быстром переключении коробок (есть `loadToken`, но не везде).
6. **`innerHTML` для пользовательских данных** — везде используется `esc()`, но любая пропущенная точка = XSS.
7. **`window.importData` глобальная переменная** — стейт-машина импорта неуклюжая.
8. **Нет undo / истории** — удалил коробку → всё.
9. **Нет логов / audit trail** — кто что когда менял.
10. **Все 2200+ строк в одном файле** — сложно поддерживать.

### Мелкие
11. Старая legacy CSS на overlay (sidebar-overlay, filter-overlay) — не используется, можно удалить.
12. `openStickerPicker` функция остаётся в коде, но больше не вызывается.
13. Хардкод: `box-id` в onclick через шаблонные строки — потенциально ломается на спецсимволах.

## 11. Запуск локально

```bash
# Вариант 1 — Python (встроен в macOS/Linux)
python3 -m http.server 8000
# открыть http://localhost:8000/

# Вариант 2 — Node
npx serve -l 3000 .
# открыть http://localhost:3000/
```

Никакой сборки не требуется. Приложение работает напрямую с CDN-зависимостями.

## 12. Контакты и хэндофф

Что важно сказать программисту:
1. Прочитай `index.html` — он самодокументирован комментариями-разделителями.
2. Начни с раздела «**Известные проблемы**» — закрытие RLS критично.
3. Дизайн-токены живут в `:root` CSS-переменных — менять цвета централизованно.
4. Все API-вызовы идут через `api(method, path, body)` — единая точка для middleware.
5. State хранится в глобальном `state = { boxes, allProducts, filtered, ... }`.
6. Mobile использует bottom-navigation паттерн — НЕ возвращай гамбургер-меню.
